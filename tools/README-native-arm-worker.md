# Build the experimental native ARM compiler worker

`build-native-arm-worker.py` builds the current repository's production converter
and worker from source. It has no dependency on a private pilot, old object files,
or a particular checkout path. It requires macOS/Xcode command-line tools, Python
3.9+, the pinned native DirectX headers, pre-existing **ARM64 LLVM 15** static
libraries/headers, and the three
Metal helper headers already generated by the normal airconv build. It does not
build LLVM, download dependencies, install binaries or enable the Wine bridge.

Use the actual directories from your dependency build. An LLVM source/build split
needs both include directories, with generated headers first. If your installed
LLVM has a complete include tree, omit the second `--llvm-include`.

```sh
python3 tools/build-native-arm-worker.py \
  --source-dir /path/to/dxmt \
  --directx-include /path/to/pinned-directx-headers \
  --llvm-include /path/to/llvm-arm-build/include \
  --llvm-include /path/to/llvm-15-source/include \
  --llvm-lib-dir /path/to/llvm-arm-build/lib \
  --helper-include /path/to/dxmt-build/src/airconv/darwin/libairconv.a.p \
  --output-dir /path/to/new-owned-worker-build \
  --check-only
```

`--directx-include` is optional when `include/native/directx` is already populated
with the pinned submodule. An empty worktree submodule is rejected before any
compilation; the builder never initializes or downloads it. Explicit overlay
headers are hashed independently of whether the repository submodule is populated.

`--helper-include` must contain `air_msad.h`, `air_samplepos.h` and
`air_tessellation.h`, generated from the repository's existing Metal helper
pipeline. Those exact bytes enter the identity; the builder does not regenerate
or silently substitute helpers. `--check-only` validates architectures, LLVM
version, source lists and inputs, hashes them, prints the prospective identity,
and writes nothing. Remove `--check-only` to build sequentially, one compiler at
a time. The output directory must be new or empty; existing files are never
reused or overwritten.

The builder reads the converter source list, LLVM link order and component flags
from their existing static Meson lists. A future non-static declaration is an
explicit error requiring a builder update. It compiles every converter/parser
translation unit and the actual worker main, then links ARM64. Common settings
are C++20, `-O1`, `-DNDEBUG`, blocks, and a macOS14 deployment target; component
flags preserve the converter's no-exceptions setting and the parser's exception
support. Compilation runs with a fixed PATH/LANG environment, so inherited
include/library/deployment/DYLD variables cannot change the build silently.

## Identity and bridge matching

The output contains:

- `airconv-worker-arm64`: the real converter executable.
- `bridge-build-id.txt`: the64-hex identity required by the matching Unix bridge.
- `build-receipt.json`: exact input hashes/paths, compiler/SDK identity, flags,
  commands, executable hash and build result.
- `build.log` and owned object files.

Identity schema `dxmt-native-arm-worker-build-v2` hashes the current converter,
bridge, protocol and recipe source/headers, selected DirectX headers, generated
helpers, LLVM archives and
header overlays in order, actual clang executable/version, SDK version, flags,
link order and builder source. Absolute checkout/dependency paths are recorded
in the receipt but excluded from the identity, allowing relocation of identical
inputs. System SDK contents are identified by SDK version and toolchain rather
than hashing the entire SDK; the receipt does not promise bit-for-bit executable
reproduction across different SDK/toolchain installations. All recorded file
inputs are rehashed after compilation to reject a mixed-source build.

Use the printed `-Dvibewine_arm_worker_build_id=<64hex>` option in the root-owned
**matched Wine/Unix bridge build**. The bridge option is empty/disabled by default.
The worker's embedded identity and the bridge's macro must match exactly; the
worker rejects every request with an old or mismatched identity. Do not reuse an
old identity merely because some files or smoke outputs look equal. A change in
identity schema also requires rebinding the bridge.

After that matched build has been validated, the explicit opt-in is
`DXMT_AIRCONV_WORKER=/absolute/path/to/airconv-worker-arm64`, set before shader
initialization. Building this artifact alone neither activates that variable nor
installs/updates Wine. Default enablement still requires representative runtime
and rendering evidence; see the lifecycle and acceptance scope in
[`tests/vibewine/native-arm-worker/README.md`](../tests/vibewine/native-arm-worker/README.md).

## Failure, bounds and retention

Each compile has a240-second deadline; link180seconds; whole compilation30minutes.
On timeout, interruption or failure the active task-owned process group is killed
and reaped. The failed receipt and bounded log remain for diagnosis. No retries
reuse uncertain objects. A rerun requires a fresh empty owned output directory.
The builder checks20GiB free space, a256MiB output cap, and a32MiB log cap.

Owner: caller of this builder. Scope: only its explicitly selected output
directory. Objects/executable expire after7days with aggregate256MiB cap;
logs7days/32MiB; receipt/minimal result evidence30days/8MiB. Active admission,
explicit pins or recovery obligations are holds. Cleanup is manual: verify exact
ownership, no running build/worker, required receipts preserved, and no holds or
symlinks before retiring known outputs. No installed cleaner or dependency
retention enforcement is provided; existing LLVM/helper inputs remain owned by
their original build.
