# Integrated FPS source wave, 25 October 2026

This is a set of independently controlled experiments, not a measured FPS release.
The ordinary Meson defaults keep all seven new optimization switches disabled.
Build a reference and a combined candidate from the same source and dependencies.
Do not infer gameplay performance from the focused CPU fixtures or syntax checks.

| Meson boolean | Compile definition | Scope |
| --- | --- | --- |
| vibewine_precise_bindings | DXMT_PRECISE_BINDINGS | Exact CB dependencies on dynamic DISCARD |
| vibewine_dead_attachment_stores | DXMT_DEAD_ATTACHMENT_STORES | Narrow full-clear overwritten color Store |
| vibewine_physical_residency_dedup | DXMT_PHYSICAL_RESIDENCY_DEDUP | Covered duplicate native declarations after pass merging |
| vibewine_residency_sets | DXMT_RESIDENCY_SETS | Bounded stable immutable raw-buffer residency |
| vibewine_idle_retirement | DXMT_IDLE_RETIREMENT | Bounded per-queue completed-idle pool sweep |
| vibewine_fixed_output_metalfx | DXMT_FIXED_OUTPUT_METALFX | Explicit render/output separation; additional runtime admission required |
| vibewine_shader_cleanup | DXMT_SHADER_CLEANUP | Exact duplicate pure integer halfword extraction cleanup |

The existing scene-submission switch remains independent. A combined build does
not automatically enable fixed-output scaling: see its configuration and SDR,
sample/aspect/size admission in [the scaler notes](fixed-output-metalfx-20261025.md).
Compiler cleanup uses local cache epoch **3**; disabled retains **2**. Both shader
database and PSO archive consume that compatibility word. Existing caches are not
deleted; reference and candidate cannot silently reuse one another's output.

Shared integration repairs make capture-start return the actual native result,
reject unsupported or already-active capture, and stop only an acknowledged
owned capture. Entry 149 appends native allocation-size lookup to both Unix
dispatch tables without shifting older entries; PE and native bridge must match.
CPU fixtures do not establish a real readable GPU trace or the Windows F10 path.
Split scene/final chunks also need explicit capture-boundary validation.

Fixed-output presentation fits the source into the actually acquired drawable
and clears exposed bars to black. Offset viewports must use UV scaling, never
the absolute-raster blit shader. Multisample scaling likewise uses normalized UV
source coordinates; the matched-size direct path is retained. These are correctness
changes in both reference and candidate, not credited as optimization gain.

## Runtime ownership and diagnostic retention

The 26 October semantic-blend-hash experiment (`vibewine_semantic_blend_hash`,
default false) adds one immutable `size_t` fingerprint member to each existing
`MTLD3D11BlendState` only when enabled: eight bytes of member payload on supported
64-bit targets; object-layout padding remains compiler-dependent. Its data class
is process-memory cache metadata, owned by the same object in the existing
`StateObjectCache<D3D11_BLEND_DESC1, IMTLD3D11BlendState>`. TTL is that owner's
existing cache/device lifetime, with cleanup by ordinary state-cache destruction.
Active and cached references remain authoritative. There is no new aggregate
state-count/byte quota, wall-clock expiry, individual live-state purge, capture
stream or background producer. The option changes a private interface and must
be consistent across the matched build; it changes no serialized cache key or
shader output. See [the measured source fixture](../tests/vibewine/semantic-blend-hash/README.md).

The 26 October packed-IR experiment (`vibewine_packed_ir_growth`, default false)
changes only each `BasicBlock::instructions` backing allocation. Its data class is
process-memory compiler IR. The owner is the block in `SM50ShaderInternal::bbs`;
TTL is that existing shader object's lifetime, potentially until pipeline-cache
teardown, with cleanup through `SM50Destroy`/block/list destruction. Active and
cached shader references remain authoritative; no live IR eviction is added.
The opt-in 1.5x policy caps each list's capacity below 1.5 times occupied bytes
after growth, apart from the existing 1024-byte small-list floor. Occupied IR and
the number of blocks/shaders have no new aggregate byte cap, and retained slack
may increase memory pressure. No wall-clock expiry, process quota or manual
purge of live objects is supported; compare memory pressure with the option off.
See [the focused allocation checks](../tests/vibewine/packed-ir-growth/README.md).

Residency owner is CommandQueue. Candidate/member identities retain at most 256
BufferAllocation owners and 64 MiB of native backing, with a 16 MiB per-entry cap.
CPU metadata/view caches are outside that backing-byte count. Cleanup occurs
after 32 completed idle sequence IDs on subsequent encoding, or drained shutdown;
this is not a wall-clock TTL. Current/incomplete/alias-used allocations retain
their ownership within the same cap. Membership removal/commit precedes release.

Idle registry owner is the same queue; each resource embeds a borrowed registration,
unregisters before member teardown and never receives registry keepalive ownership.
It admits 4096 owners and sweeps at most 16 owners/128 entries/64 releases/64 MiB
per completion. Current/inflight/recorded/external references remain authoritative.
Excess pool references age for 300 completed sequences. Unknown/oversized backing
can remain held; this is not a global process-memory cap or cache purge.

With DXMT_IDLE_ATTRIBUTION=1 and the idle experiment enabled, the finish thread
reports at most 64 snapshots, one per ten seconds, each less than 1 KiB, into the
existing stderr route. No new file, service or worker is created. Categories are
counts/charged bytes/unknown-byte counts for the visited partial scan; unvisited
owners and unclassified tails remain explicit. Released values count pool
references and backing charge, not reclaimed RSS. Optional stderr writing can
perturb timing and must be controlled in comparisons.

For managed captures the existing telemetry owner retains raw diagnostics seven
days under the 256 MiB session cap; curated summaries use 30 days/4 MiB. Active,
analysis and recovery holds remain. Outside managed capture, the caller owns
stderr storage/cleanup. Test scratch belongs to each bounded temporary runner
and is removed on exit. No automatic cleanup or unrelated data scope is added.

Explicit-discard S2 intent is owned by the existing command chunk or deferred
command list: each admitted API call retains one Texture Rc plus one 64-bit view
key (16 bytes of payload on the supported 64-bit target, excluding existing
command-node overhead). No independent persistent registry, texture allocation,
new logger or background producer is added. Lifetime follows the existing
chunk/list, including caller-held replayable lists; cleanup releases the capture
when that owner resets or is destroyed. The encoded action change occupies the
existing attachment field. A flush resets the encoder list, so there is zero
pending intent across command buffers. There is no new aggregate hard cap over
application-owned deferred lists; their existing ownership remains authoritative.

S2 raw fixture executable/log/capture evidence is owned by the root performance
wave under its private run directory, capped at 64 MiB with a seven-day TTL.
Active, analysis and recovery holds exclude held inputs from cleanup. Source
checkout and curated source/tests/decisions are durable results outside that raw
cap. Cleanup is manual after owner/process closure and reference/hold validation;
this policy installs no automatic cleaner. CPU runner scratch is a task-owned
temporary directory removed on exit. No unrelated data is in scope.

## Validation and remaining acceptance

Focused production-source tests cover precise bindings, pass optimizations,
residency sets, idle retirement, fixed output, capture validity, presenter command
equivalence and shader cleanup. Their individual READMEs state exact coverage,
baseline/mutation controls and platform limits. Run the idle diagnostic contract
with `python3 tests/vibewine/idle-retirement/diagnostics.py`.

The integration owner built both complete 161-target release variants from
`36385509` (public tree-equivalent `cb5fa11d`), with matching Wine Unix NTDLL
and wineserver. PE/native compiler defines agree; only the seven booleans above
and existing scene-submission switch differ. LLVM is the retained 15.0.7 build.
Both variants passed all five offscreen D3D11 stages with live process-birth,
mapped-library and unchanged-hash proof. Dedicated pass checks passed four cases
and five pixel images on each variant; a changed expected pixel was rejected
after actual GPU readback. The production Metal helper from each full build also
passed all six single/MSAA/offset/scaled image cases and the changed-golden
control in the [native shader fixture](../tests/vibewine/capture-validity/gpu/README.md).
The initially delayed module output was rejected, then the fixture was repaired
to use unbuffered output and a bounded external mapping acknowledgement.

These checks do not exercise dynamic DISCARD dependencies or prove immutable raw
buffer admission into residency sets. Real pool memory effects, contested WaitAll,
the actual MetalFX scaler, production presenter/CAMetalDrawable, readable capture
and split capture boundaries remain open. Actual launch/gameplay/exit/relaunch,
installation and controlled performance remain integration-owner gates. Compare each switch
and then the combination at the same scene/render/output/power/cache conditions.
Reject benefits within A/A variation, shifted waits, increased latency/queue depth,
unexpected pixels, failed scaler quality criteria or worsening memory pressure.
No lower-precision FP math, frame generation, native ARM wineserver, all-live
residency pinning or atomic multi-object WaitAll redesign is included here.


## Memory-owner follow-up — 28 October 2026

The [IR compaction follow-up](ir-compaction-20261028.md) preserves the existing
`SM50ShaderInternal::bbs` / BasicBlock owner and shader-lifetime TTL. It reduces
only unused capacity of unpublished instruction lists after cloning; successful
shrink caps that allocation at its occupied byte count, while failed or below-
threshold shrink retains the previous capacity. The occupied IR, number of
shaders/blocks, parser peak and allocator size bins have no new aggregate cap.
Cleanup remains normal shader/list destruction. Active, cached, late-variant
and paired-stage users retain their instructions; no live eviction, manual
purge, wall-clock expiry, new DXBC copy or independent retention owner is added.

Reference-tracker node storage is ordinary host heap memory owned by each
CommandQueue's existing 4 KiB ring. The finish thread now invokes its existing
`free_blocks` after tracker clear/detach and CPU coherence. The exact existing
ring grace applies: excess completed standard blocks expire after more than 300
sequence distance or cleanup-call aging; one completed standard block stays warm.
Pending/current chunks remain excluded by sequence identity and the ring mutex;
external resource references remain independently owned. There is no hard total
byte cap, no wall-clock TTL and no cleanup progress without later completions.
Queue teardown remains the final lifetime. No kernel memory-pressure eviction,
resource relocation or GPU ownership rule changes. Cleanup inherits linear
scan/erase under the existing mutex; a time-budget guarantee is not claimed.

Neither change adds a producer, file, worker or service. The exact process-memory
scope above is distinct from telemetry/raw-evidence retention, whose existing
caps, TTLs and active analysis/recovery holds remain unchanged. Private build
scratch has its own wave-owner contract; source/tests/decisions are durable Git
results. No installed cache or game data is erased or migrated.
