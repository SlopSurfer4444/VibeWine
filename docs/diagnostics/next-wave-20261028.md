# Eight-direction continuation — 28 October 2026

This wave follows the frontier checkpoint. It combines general CPU reductions,
two opt-in native compiler routes, Wine synchronization/native focus repairs and
stricter measurement admission. [The component contract](../../components/dxmt/docs/next-wave-20261028.md)
describes enabled/disabled behavior and remaining compiler/GPU limits.

## Source changes

DXMT lazily prepares requested buffer views, memoizes alternate texture views,
propagates speculative compute intent and actual demand promotion, avoids
variant-cache poisoning after factory exceptions, and recycles ring nodes without
reallocation. These mechanisms do not inspect DS3. Old-fail/new-pass and connected
negative controls cover actual production owners; native pixel adapters cover
the changed view paths.

Metal4 creation is build-off/process-off by default. The persistent ARM worker
is also disabled without an exact matching identity and explicit path. Its
portable builder compiles all current converter/parser units against supplied
ARM LLVM15 dependencies and generated helpers; no rollout-specific object files
are required. Native compiler tests, image/recipe parity and lifecycle controls
are not an installed or gameplay claim. Native archives and AIR output meanings
retain their existing scope/epoch.

Wine negative relative deadlines now use its actual QPC100ns monotonic units;
positive absolute deadlines retain system time. Retry/chunk conversion clamps
overflow and preserves zero/infinite/APC behavior. An atomic minimum free hint
prevents lower holes being stranded and removes its cross-thread hint race.
Stable-table header registration is now present in Wine's global Makefile
registry: fresh configure exposed that earlier missing build-system dependency.

Native cursor confinement releases on key loss and rejects stale/off-Space
capture requests, binds to the correct key-window owner, and rebinds same-rect
requests after owner changes. Existing native permission-dialog/internal-switch
exceptions remain. CPU/native-source fixtures do not prove Mission Control
callback delivery or fix direct cursor warps; those remain live gates.

## Measurement and adoption boundaries

The portable repeatability analyzer recomputes windows from raw decoded data and
clock envelopes, rejects loss/replayed identities/control or module drift, and
preserves A/A spread and run order. It does not invent scene classification,
causation or an FPS improvement.

A private collector successor validates preflight before ready, binds readiness
to a live observer birth/expiry, revokes stale ready on terminal states, reports
nonzero failures and bounds source/decoded storage. It remains outside this
public source because its preexisting private ownership is retained. The
user-helper successor uses existing delivery transactions and explicit cold
combined trace routes. Those routes retain zero raw game stdout/stderr through
the null sink; stderr-only MSync/idle attribution is unknown/not covered. Actual
profile metadata and native frame data must prove capture activation.

The normal native1080/no-upscale selection, saved games, network/VPN and recovery
are preserved. Ordinary helper updates, matched runtime delivery and actual
loaded modules/gameplay are independently checked. The ARM worker is not a new
schema12 runtime slot; its deployment/activation remains separate from the
ordinary matched bundle. Metal4 request/activation must also be distinguished.
