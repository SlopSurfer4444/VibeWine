| Lane | Shared implementation | Deliberate boundary |
| --- | --- | --- |
| P1 | Dirty only matching bound constant-buffer dependencies after dynamic DISCARD, including aliases | Existing broad behavior for other resource classes remains |

Presentation also fits actual acquired drawable geometry, clears bars, and uses
normalized source coordinates for offset/MSAA scaling. These correctness repairs
are common to reference and candidate and cannot be credited as an A/B speed gain.

## Checks performed

Focused source-extracted production fixtures passed on native arm64 and
x86_64/Rosetta with the documented sanitizers and connected old-fail/mutation
controls. The relevant fixture directories document coverage and commands:
`precise-bindings`, `pass-optimizations`, `residency-sets`, `idle-retirement`,
`fixed-output-metalfx`, `capture-validity` and `shader-cleanup` under
`components/dxmt/tests/vibewine`, plus Wine's MSync suites. Independent source
review found and led to repair of final-frame capture shutdown and repeated
residency-size lookup before the final build.

Both complete 161-target DXMT release builds linked against the matched Wine
Unix NTDLL/server and retained LLVM 15.0.7. The eight option differences are
exactly the seven new switches plus scene submission. PE/native definitions
match. The first attempt failed because the production Metal shader lacked
`metal_integer`; that header was added, the whole Metal translation unit passed,
and the fresh complete build pair succeeded. Initial failed receipts remain held.
This does not constitute a complete production-feature Wine distribution rebuild.

On the actual GPU, sequentially in the private authless sandbox:

- Both variants passed all five generic offscreen D3D11 stages: draw, MRT/depth,
  compute, MSAA4, and later-chunk query progress.
- Both variants passed four dedicated pass-optimization cases with five exact
  pixel images, including preservation of an intervening copy. The candidate's
  changed-golden control naturally failed after actual readback.
- The production Metal helper from each full build passed six native pixel
  cases: single/MSAA4, matched/offset/scaled viewport, including black bars.
  Both changed-golden controls naturally failed after GPU completion.
- Each Wine GPU run independently verified live PID/birth, all seven required
  PE/native mappings, admitted file hashes before/after, and private-server cleanup.

An initial output-only run, an incorrect sandbox acknowledgement path, and a
buffered pass-test module report were rejected rather than upgraded to success.
The test handshake now waits at most 15 seconds; process identity proof belongs
to the external runner. Final guest binaries were rebuilt and rerun.

GPU behavior or P3's actual immutable-buffer residency admission. Real pool memory
effects and contested WaitAll behavior also need targeted runtime tests.
Native shader pixels do not establish the actual MetalFX scaler, production
presenter/CAMetalDrawable, displayed output, resize/input geometry or a readable
GPU trace. Split scene/final capture boundaries remain open.

metrics. The true build and the explicit diagnostic-launch helper were installed
