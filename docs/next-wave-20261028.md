# CPU economy and native compiler routes — 28 October 2026

Local continuation of `8d0cef8d`; general mechanisms have no game-name test.
Existing component licenses and source attribution are retained. This document
describes source/build acceptance, not installed feature activation or FPS.

## General changes

- Buffer views materialize only the prefix needed by the requested key.
  Successful appends advance allocation-local progress individually. Existing
  nil-native-view behavior remains unchanged; later high keys, rename and old
  allocations retain their identities and residency state.
- Array/nonarray texture conversion remembers one bounded alternate key per
  descriptor, under the existing descriptor lock. New format aliases reset that
  memo; conversion is not assumed reversible after array-size normalization.
- Compute prewarm carries speculative urgency through both shader and PSO.
  A real consumer promotes the existing PSO and its dependency. Existing worker
  capacity, fairness and disabled-scheduler behavior remain owners.
- Shader variant construction precedes map publication, so a factory exception
  does not permanently poison that key with a null entry. General scheduler
  allocation/Run exception recovery remains separate.
- Completed ring blocks move through their FIFO with list splice. This avoids
  node allocation/deallocation and preserves Block identity on reuse.

Actual-owner CPU fixtures reproduce old failures and count operations. Native
Metal adapters check buffer/texture output against independent pixel oracles.
Eight-to-two native creations or zero recycled-node allocations are fixture
results; no per-frame frequency or FPS gain follows from them.

## Metal4 compiler experiment

`-Dvibewine_metal4_compiler=true` builds a capability-gated route. It additionally
requires `DXMT_METAL4_COMPILER=1` before process initialization. The ordinary
command encoders and PSO ABI remain in use. Supported compute/render recipes
preserve function constants, resources, blend/write masks, raster/sample state
and the checked Depth32Float/no-stencil path. Archive/serialization, indirect,
logic-op, patch and unsupported depth/stencil recipes explicitly use legacy
creation. A selected supported route that fails returns failure; it does not
silently retry legacy creation. Old SDK/OS/device and disabled paths stay legacy.

The bridge retains immutable function provenance and copied specialization
values before publication. Native tests extract the actual factories/helper
under their manual-reference-counting contract, including errors, nil results,
pool drain, resources/constants, blend/masks, MSAA, depth and capability guards.
The expanded corpus is MSL. Earlier translated Wine shader evidence is separate;
representative game shader activation/performance is not established here.
No AIR output/cache epoch change or new persisted native archive is introduced.

## Persistent ARM compiler experiment

The Unix compiler thunks can use one persistent native ARM converter while the
existing synchronous task, ManagedShader and cache-publication owner remain.
Ordinary VS/PS/CS recipes serialize all nine public argument node kinds;
paired compilation and WOW64 remain local. Input/response/build identities,
reflection parity, bounded ownership and child lifecycle are explicit.

The bridge is disabled unless its build has an exact 64-hex
`vibewine_arm_worker_build_id` and the process receives an absolute
`DXMT_AIRCONV_WORKER` path. Empty identity is the normal build default. The worker
is a separate artifact; compiling WineMetal does not install or activate it.
Use [the portable full-source builder](../tools/README-native-arm-worker.md)
and its emitted matching bridge option. No private prior objects are required.

Default/unsupported/contention/definite spawn failure can stay local before
dispatch. After dispatch, transport failure/crash/deadline/cancellation returns
an error and reaps the child without in-host replay. This is transport shutdown,
not application task cancellation: the current task owner has no such API.
There is no hard LLVM heap sandbox. Runtime data caps, child rotation/idle
expiry and error/bitcode lifetime are documented in the fixture README.

Complete AIR/reflection parity, persistent rotation, concurrency and failure
controls pass in standalone integration. Native PS pixel parity and VS/CS
completion are deliberately distinct evidence. Warm fixture conversion can be
faster including IPC; cold startup and actual game benefit remain separate.

## Held work and tests

The native derivative experiment did not justify a faster production lowering.
Allocation/device-error propagation remains held: existing consumers can reach
null placement construction and publish readback during precommit unwind. The
ring splice does not repair these; see queue-failure-contract/README.md before
designing device removal or cancellation. Partial error handlers were excluded.

Portable tests include cpu-view-economy, compute-prewarm, native-arm-worker,
queue-failure-contract and all existing cross-regressions. Native Metal4 tests
require a supported SDK/device and an explicit private output directory. Keep
generated binaries/logs out of source and use the tests' bounded scratch rules.
Both complete renderer variants and affected Wine targets are separate build
gates; installation, loaded modules, normal exit/relaunch and game timing need
their own admitted observations.
