# Initializer creation callers

Run `python3 tests/vibewine/initializer-creation/run.py`. Optional `--source-dir PATH` selects a checkout; `--arch arm64` or `--arch x86_64` selects a macOS target. Requires Clang with AddressSanitizer and UndefinedBehaviorSanitizer. Exceptions remain enabled.

The runner snapshots and extracts the current production buffer constructor, complete `Initialize`, complete `CreateBuffer`, complete `CreateDeviceTextureInternal` including its function try block, fresh Mach send-right guard, and texture-owner constructors, handle adoption, and destructor. It compiles those bodies unchanged with the actual `Rc` implementation. Platform descriptors, subresource enumeration, allocations, initializer queue, and the surrounding COM ownership adapter are CPU mocks. No production creation bodies are copied into fixtures or recreated by the tests.

The matrix covers zero/data failures at each of six subresources, retained successful prefixes after descriptor destruction, both HRESULT failure categories, null native and null wrapper allocations, buffer usage/storage flags and paths, renamable allocation and initialization failures, normalized descriptors, shared initialization/publication ordering, and keyed-mutex/D3DKMT/bootstrap failures. `std::bad_alloc` is injected through class `operator new`: texture/buffer/COM-owner/dynamic/pool faults occur at `new` expressions in the extracted production bodies; texture/buffer allocation-wrapper and keyed-mutex faults occur at the mocked allocation endpoints. Successful regular/shared/renamable textures and buffer uploads/clears are checked against independent nonzero byte patterns or zero goldens after the mock queue drains. Those goldens verify caller argument forwarding and completion ordering through the mock edge; production upload encoding, native texture layouts, and actual initializer execution are tested elsewhere.

Negative controls remove failure mapping, result handling, native texture validation, shared-handle adoption, or unpublished Mach right release. Each must fail its intended assertion without a sanitizer crash. Every run prints the actual case count and source/fixture/generated hashes. Successful candidate and deliberately rejected controls are reported separately.

Allocation accounting establishes mock wrapper/native storage lifetime, retained prefix ownership, exact D3DKMT resource destruction through the extracted destructor, and exactly one deallocation bridge call for each fresh unpublished Mach right on failure. It verifies pending allocation lifetime remains independent of that right. Successful publication follows the existing retention policy. This does **not** establish native Mach send-right release, bootstrap service removal, native keyed-mutex cleanup, real COM reference counting, or installed runtime/GPU/game behavior. Actual native deallocation bridge behavior is outside this caller fixture.

An allocation-edge mock throws before producing its native right. It therefore does not cover an exception inside the real `Texture::allocate` after `newSharedTexture` has produced a right but before `TextureAllocation` construction returns. Producer-level exception cleanup requires separate coverage at that lower boundary.

The runner creates one private temporary directory, removes it on success or failure, uses 60-second compilation and 30-second execution deadlines per variant, and checks a 64 MiB scratch cap. No service, installed runtime, game, persistent collector, or repository-generated binary is changed.
