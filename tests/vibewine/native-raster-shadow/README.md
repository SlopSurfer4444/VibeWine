# Native raster shadow experiment

Default-off `DXMT_NATIVE_RASTER_SHADOW=1` keeps an immutable raster-command pointer only during one synchronous native render decoder call. The first command sends all five selector groups; later commands send changed groups. Integer fields compare by value, each of the three float fields by its own representation. Link/reserved/padding bytes do not participate. ICB execution and unknown opcodes invalidate the local shadow. No state is retained by encoder handle or across calls; no resource/ABI/fence/viewport/scissor behavior changes.

The root integrator owns exposing the default-off option in the common matched build flag mapping. This isolated change deliberately edits only the decoder and its tests.

Run `python3 tests/vibewine/native-raster-shadow/run.py --bench`. This extracts the whole production native render decoder into a CPU Objective-C receiver using the actual command ABI. Three explicit void-pointer casts adapt the C function to Objective-C++; its loop/switch is otherwise unchanged. ASan/UBSan compare draw-visible mock state and all other invoked selectors against the default/off path. ICB mutation changes mock raster state. Removing ICB invalidation and replacing float-bit comparisons with numeric comparisons must fail the controls. Full original production Objective-C translation-unit syntax is checked with the option on, in Wine and native modes. No Metal device, command buffer, GPU, Wine or game is created.

Controls include empty, singleton, exact repeat, each individual field change, all-fields change, signed zero, equal/different NaN payload, differing reserved bytes, ICB state mutation, separate decoder calls, unknown opcodes under NDEBUG, nil encoder, viewport/scissor arrays and vertex-buffer unbind. Full native syntax is checked with assertions enabled; unknown-opcode fixture executes NDEBUG's existing default path.

The optional ABBA microbenchmark compares one raster command and two-command lists with equal, cull-only and all-field-changing payloads. It includes list relinking and cheap mock selectors. It is a diagnostic of this fixture, not real Metal CPU cost or FPS. Accepting the option in production requires real selector/run multiplicity, bounded paired CPU measurements above A/A noise, preserved pixels/query progress, and no regression in singleton/change-heavy scenes or frame tails.

Run `python3 tests/vibewine/native-raster-shadow/patterns.py` for controlled production render-emission and optimizer patterns, reusing the existing fixture generators. It compares resource declaration runs before/after existing dedup and verifies Clear→Clear, Clear→Clear→Render, and Clear→Timestamp→Clear. The 256-scenario emitter uses duplicate declarations and is not a game-frequency sample. In that fixture dedup makes all surviving resource runs singleton, leaving no adjacent-useResources saving. GS/TS transport changes can create new runs and require another measurement. No resource grouping or clear coalescing is implemented here.

A safe resource-grouping follow-up would group only physically adjacent nonnil UseResource nodes with exactly equal usage/stages; preserve singleton/zero-mask paths, order, counts and masks; stop at Nop/draw/barrier/fence/bind/other opcodes. It would reduce Objective-C selectors, not PE crossings or GPU operations. Apple documents the array API as making those resources accessible to subsequent draw commands: https://developer.apple.com/documentation/metal/mtlrendercommandencoder/useresources(_:usage:stages:)

A clear-coalescing follow-up first needs measured residual adjacent full-color clear frequency after existing folding. Restrict any proof to original adjacency, exact current physical allocation/base view/full extent/array, private nonheap nonshared storage, no query/event/read/alias boundary; retain latest clear color, merge signal provenance and inherited waits, subtract only proven internal waits, and retain proper ownership. The current fixture shows that dropping the earlier clear without transferring its signal strands the later clear's wait. Existing Clear→Clear→Render already folds both, so that case offers no extra saving.

Apple's current feature table includes ICB raster/depth-stencil state on supported devices; treating ICB contents as raster-preserving is unsafe: https://developer.apple.com/metal/capabilities/
