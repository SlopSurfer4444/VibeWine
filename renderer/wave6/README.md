# Wave6 integrated DXMT source

`source` is the exact final integrated production text, including all Wave5 changes plus the audit repairs and opt-in DS3 owner-thread borderless route. Two upstream PNG tests are omitted as in earlier snapshots. `source.patch` reconstructs this tree from `../diagnostic/source`. Retained Wine and renderer histories elsewhere in this repository describe older generations; Wave6 current observations are in `live-result.json`.

Run `python3 tests/run_wave6.py` from the repository root on macOS with Python 3 and Xcode Command Line Tools. Everything compiles/runs in disposable copies. No Wine, game, profile or installed runtime is touched. Source-extracted control-flow tests use Win32/COM doubles; their success does not prove hardware/compositor ABI behavior.

For an isolated Windows renderer build, set `LLVM_MINGW` to the LLVM-MinGW compiler bin directory, `DXMT_RELEASE` to the matching external v0.80 release directory, and `WINEBUILD` to a compatible winebuild executable, then run `python3 build.py` here. `xxd` must be available. The observed build used llvm-mingw-20260826-ucrt-macos-universal and built all 69 translation units. `helper-library.json` pins the donor d3d11.dll and extracted embedded Metal helper. The exported script records its output hash in `build/build.json`; compare PE export names/ordinals and the helper hash with `verification.json`. Binaries, donor DLLs, toolchains and the private source archive are excluded. The receipt proves the observed build, not a byte-identical build on arbitrary toolchains or a complete Wine runtime rebuild.

The DS3 route requires explicit DXMT_DS3_BORDERLESS=1, the exact executable suffix, owning thread/process/root window and safe capture policy. It preserves requested render dimensions independently from monitor-sized geometry; zero resizes retain the recorded dimensions. Initial and explicit exclusive requests are refused for this route. Existing native aspect-fit donor and launcher capability/aspect binding are external prerequisites; the private management harness is excluded. The old external cross-process helper is suppressed only when that bound capability is used. Other routes retain prior policy.

`smoke/fixture.cpp` is the source of the disposable D3D11 readback fixture. Prior observed smoke passed 10 windowed and 15 borderless readback points, monitor-sized borderless client/outer HWND, retained 1920x1080 for zero resize, explicit 1280x720, minimize/restore and normal WM_CLOSE. Both fixture processes naturally exited zero before scoped cleanup. This is separate from DS3 normal-exit acceptance.

The actual DS3 renderer module was observed at the hash in provenance; user confirmed full display without Dock/frame and working controller. Final-build normal game exit, displayed FPS gain, native presented-time feedback and real-game CUA remain unverified. See root `WAVE6_AUDIT_DISPOSITIONS.md` for every fixed, retained and deferred finding.
